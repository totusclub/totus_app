# Maestro: ежедневный прогон приложения Totus Club

Сценарии проходят приложение так же, как ежечасный чекап проходит сайт: поиск → отель → номер → перелёт → бронирование. Запускаются на Mac с подключёнными iPhone, iPad и Android. Отчёт — таблица «устройство | сценарий | статус | время | причина» и скриншоты.

## Сценарии

| Файл | Тег | Что проверяет |
|---|---|---|
| `flows/00_fresh_install_onboarding.yaml` | `fresh` | Стирает данные приложения, проходит онбординг (4 × «Далее» → «Я согласен»), сразу главная без PIN-кода, вкладки на месте. **Выходит из аккаунта**, поэтому в ежедневный набор не входит. |
| `flows/01_launch_and_tabs.yaml` | `daily` | Запуск, форма поиска (Москва → Египет), вкладки «Заказы» и «Аккаунт» открываются. |
| `flows/02_tour_search_to_login.yaml` | `daily` | Тур с перелётом: «Найти» → «Найдено N отелей» → первый отель → «Выбрать номер» → «Все варианты» → первое предложение → «Выбрать N ₽» → «Найдено вариантов: N» → первый рейс → «Перейти к бронированию» → гость видит «Вход», QA-учётка — форму бронирования. |
| `flows/03_hotel_only_to_booking.yaml` | `daily` | Отель без перелёта: тот же путь до формы бронирования. Форма не заполняется. |
| `flows/04_mila_chat_opens.yaml` | `auth` | Вкладка «Totus AI»: чат Милы открылся, статус «Онлайн · подбор туров», поле ввода на месте. |
| `flows/05_support_chat_opens.yaml` | `auth` | «Аккаунт» → «Чат с поддержкой»: экран и поле «Напишите сообщение…» открываются. |

Общие шаги — в `subflows/`: старт приложения (`start.yaml`), онбординг, закрытие системных окон (отслеживание на iOS, уведомления, шторка «Включить уведомления?» — везде «не разрешать» / «Не сейчас»).

## Чего сценарии никогда не делают

- не вводят текст: ни почту, ни имена, ни паспорта — никаких персональных данных;
- не нажимают «Войти», «Отправить запрос», оплату, «Выйти», «Удалить аккаунт», «Позвонить»;
- не пишут Миле (каждое сообщение — платный запрос к модели) и не пишут в поддержку (сообщения увидят живые сотрудники).

Кнопка «Выбрать N ₽» создаёт в API пакет тура — так же, как «Выбрать» на сайте. Это не заказ и не бронирование.

Правила проверяет `scripts/check-maestro-flows.mjs` (входит в `npm run check`). Он же сверяет, что каждая надпись, которую ждут сценарии, есть в коде `src/`: переименовали кнопку — проверка упадёт раньше утреннего прогона.

## Подготовка Mac (один раз)

1. Maestro: `curl -fsSL "https://get.maestro.mobile.dev" | bash`, затем новый терминал и `maestro --version`. Нужна Java 17+ (`brew install openjdk@17`).
2. Android: `brew install --cask android-platform-tools`. На телефоне — «Для разработчиков» → «Отладка по USB», подключить кабелем, подтвердить отпечаток Mac. `adb devices` показывает устройство со статусом `device`.
3. iOS: Xcode и Command Line Tools. Надёжный вариант — симуляторы iPhone и iPad (Xcode → Settings → Platforms) со сборкой приложения для симулятора. Реальные iPhone / iPad по кабелю Maestro поддерживает в последних версиях не во всех конфигурациях — если прогон на них падает на запуске, оставляем симуляторы.
4. На каждом устройстве стоит та сборка приложения, которую проверяем (из сторов, TestFlight или собранная локально). Bundle id: iOS `app.totus.club`, Android `com.totus.com`. Другие — через `IOS_APP_ID` / `ANDROID_APP_ID`.
5. Для сценариев `auth` один раз войти в приложении на каждом устройстве **QA-учёткой** (не личной и не демо-учёткой Apple), у которой включён доступ к ИИ. Вход сохраняется: ежедневный набор данные не стирает.

## Запуск

```bash
scripts/maestro-checkup.sh            # daily на всех устройствах
scripts/maestro-checkup.sh --auth     # daily + Мила и чат поддержки
scripts/maestro-checkup.sh --fresh    # только чистая установка и онбординг
scripts/maestro-checkup.sh --only android
```

Один сценарий на одном устройстве (отладка): `maestro --device <id> test .maestro/flows/02_tour_search_to_login.yaml -e APP_ID=com.totus.com`.

Результат: `reports/maestro/<дата_время>/SUMMARY.md` — первая строка «ВСЁ РАБОТАЕТ» или «ЕСТЬ ПРОБЛЕМЫ: …», дальше таблица по устройствам и сценариям. Рядом — JUnit XML, логи и скриншоты каждого устройства. Папка `reports/` в git не попадает.

Код выхода: `0` — всё прошло, `1` — есть упавшие сценарии, `2` — нет Maestro или ни одного устройства.

## Ежедневный запуск через Claude

Запланированная задача, привязанная к этому Mac, утром запускает `scripts/maestro-checkup.sh` в папке totus_APP и присылает `SUMMARY.md` с выводами. Mac в это время должен быть включён и не спать, устройства — подключены и разблокированы.

## Как поддерживать

Сценарии ищут элементы по надписям на экране, а не по `testID` (в коде их почти нет). Если меняются тексты кнопок, заголовков или вкладок — поправить соответствующий шаг в `flows/` и прогнать `node scripts/check-maestro-flows.mjs`. На iOS текст внутри нажимаемого блока сливается в одну подпись (например, «Тур, С перелётом»), поэтому в части шагов стоят шаблоны вида `.*Москва.*`.
